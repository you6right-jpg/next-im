# 部署、升级与恢复

## 环境分层

- local：开发者本地。
- test：自动化测试。
- staging：预发布。
- production：生产。
- private：客户私有化环境。

## 容器要求

- 镜像不可变并带版本号。
- 配置通过环境变量或挂载配置注入。
- Secret 不写入镜像。
- 容器提供 readiness / liveness。
- 服务支持优雅关闭。
- Worker 关闭时停止领取新任务并处理在途任务。

## 数据库迁移

采用 expand-contract：
1. 先增加兼容字段 / 表。
2. 发布同时兼容旧、新 schema 的应用。
3. 回填数据。
4. 切换读写。
5. 确认旧版本退出后再删除旧结构。

每个 Migration 必须可审查，生产执行前有备份和回滚 / 前向修复方案。

## 备份与恢复

- 定义 RPO / RTO。
- 数据库定期全量和增量备份。
- 对象存储启用版本或备份策略。
- 定期恢复演练。
- 记录恢复步骤和验证结果。
