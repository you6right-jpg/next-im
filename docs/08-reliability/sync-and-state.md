# 同步与状态模型

## 游标模型

建议以会话 seq 为消息顺序基础，同时维护设备或用户维度的同步进度。

同步请求概念字段：
- device_id
- conversation_id
- last_seq
- limit

同步响应概念字段：
- conversation_id
- messages
- max_seq
- has_more

## 状态边界

- `last_seq`：客户端已持久化并确认处理的连续序列位置。
- `read_seq`：用户已读到的会话序列位置（需明确产品语义）。
- `delivered_seq`：仅在定义了连续送达语义时使用；否则采用消息级状态。
- 会话未读数由服务端规则或可重建的派生数据维护，避免多端各算各的。

## 重要约束

不能简单把“最大收到 seq”当作“连续已处理游标”。如果 seq=10 未收到但 seq=11 已收到，游标不能直接推进到 11。必须使用连续确认或缺口集合策略。
