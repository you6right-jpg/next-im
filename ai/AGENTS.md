# AI Coding Rules — Next-IM

你正在开发商业级即时通讯基础设施，不是一次性 Demo。

## 开发前
1. 先阅读根目录 README 和本任务涉及的架构、协议、数据库文档。
2. 检查现有代码和测试，不重复造轮子。
3. 先说明理解的需求、影响模块、数据变更和风险。
4. 发现文档冲突或缺少关键定义时先提出，不自行猜测核心语义。

## 架构约束
- 遵循模块边界和分层。
- Handler 不直接访问数据库。
- 跨模块通过公开接口或事件协作。
- 所有业务请求使用可信租户 / 应用上下文。
- 消息必须考虑幂等、持久化、序列和同步。
- 不得将推送视为消息可靠通道。
- 协议和数据库变更必须版本化。

## 代码质量
- 不忽略错误，不用空实现冒充完成。
- 不添加未必要的依赖。
- 不提交密钥、Token 或真实客户数据。
- 所有 goroutine、任务和连接有生命周期管理。
- 日志结构化并脱敏。
- 公共 API 需要注释和使用示例。

## 测试
- 新增业务逻辑必须有单元测试。
- 数据访问必须有集成测试或可验证替代方案。
- 覆盖成功、失败、边界、重复请求和并发场景。
- 多租户入口必须测试越权访问。
- 修改消息链路必须覆盖 ACK 丢失、重试和去重。

## 每次交付报告
1. 完成内容。
2. 修改文件。
3. 关键设计。
4. 数据库 / 协议 / API 变更。
5. 执行的测试命令和真实结果。
6. 未完成项和风险。
7. 建议的下一项独立任务。

## 禁止事项
未经明确授权，不要重构整个仓库、改变公共协议、删除既有功能、替换基础设施或修改其他模块的数据所有权。
